= Explanation: How docs stay correct

This portfolio project uses a docs-as-code workflow so reference docs stay aligned with the mock API and SDK.

== Sources of truth

* API behavior: `notification-hub-service/src/server.ts` and tests (`src/server.test.ts`)
* API reference: generated OpenAPI (`tsoa spec` → `docs/api/swagger.json`) → published Swagger UI
* SDK reference: generated TypeDoc (`docs/sdk/`) → published TypeDoc site
* Guides and tutorials: this Antora hub (human-authored AsciiDoc)

== What CI does today (`notification-hub-service`)

On every push and pull request:

* Validate Markdown with Vale and check links with Lychee
* Run API tests
* Validate the OpenAPI spec
* Build SDK docs (TypeDoc) and API docs (static Swagger UI)
* Attach provenance metadata (`meta.json`) and inject build banners

On push to `main` only:

* Publish SDK docs to https://sophias-hub.github.io/docs-sdk/
* Publish API docs to https://sophias-hub.github.io/docs-api/
* Run the *Docs hub agent* workflow: classify the code change with Diátaxis, update the matching AsciiDoc page(s) in this hub via Gemini, and open a pull request labeled `generated-docs` (no auto-merge)

Interactive Swagger Try it out uses the public mock API URL from the `PUBLIC_API_URL` GitHub Actions variable.

== Versioning and compatibility

Published API and SDK reference docs are *latest-only*.

* They track `notification-hub-service` on `main`
* There are no per-tag or per-release doc sets
* Each published site shows the source commit and build time in the provenance banner

== AI/agent policy

* On service `main` code merges, an automated agent proposes hub updates via pull requests with reviewable diffs
* The agent picks Diátaxis pages (tutorial / how-to / reference / explanation / operations) from the change, then edits those files only
* Human-authored guides in this hub must be reviewed before merge (PRs are labeled `generated-docs`; no auto-merge)
* Generated reference sites (`docs-sdk`, `docs-api`) still update automatically from `main` when CI passes
